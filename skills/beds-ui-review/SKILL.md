# 界面走查与设计验收（Design QA）

## 描述

把资深设计师的走查习惯固化为可执行的检查清单。对已有页面（代码或截图）逐项核对，输出**按严重级别排序的问题清单 + 具体修复建议**，而不是泛泛地说"这里可以优化"。

基准规范为 `beds-design-system`（主色 `#2563EB`、正文 14px、行高 ≥40px、圆角 ≤8px、间距 4px 网格）。

## 使用场景

- 页面/功能上线前的视觉走查
- 审查同事或 AI 产出的页面是否符合规范
- 设计稿与实现对比（还原度检查）
- 代码评审中夹带的样式检查

## 指令

### 第 1 步：确定走查对象与范围

明确要检查的文件 / 页面 / 截图，以及它属于哪类页面（列表页 / 表单页 / 统计页 / 大屏 / 通用组件），据此选取对应的专项清单。

### 第 2 步：按清单逐项核对

**A. 色彩**
- [ ] 是否严格使用令牌色，有无自造色 / 原始色阶（如 `blue-500`）
- [ ] 主色是否为 `#2563EB`，是否出现多套主色
- [ ] hover / active / disabled 三态颜色是否齐备
- [ ] 暗色场景下文字对比度是否 ≥4.5:1

**B. 字体排版**
- [ ] 正文是否 14px / 22px；字号是否都来自字号层级
- [ ] 字重是否 ≤3 种（400 / 500 / 600）
- [ ] 数字是否启用 `tabular-nums` 且右对齐
- [ ] 是否存在斜体、艺术字体、非链接下划线

**C. 间距与布局**
- [ ] 间距是否全为 4 的倍数且落在 4/8/12/16/24/32/48
- [ ] 卡片内边距是否 24px、页面边距是否 24px、卡片间距是否 16px
- [ ] 栅格是否对齐，是否出现元素错位 / 不齐

**D. 圆角与阴影**
- [ ] 圆角是否 ≤8px（Tag 2px / 控件 4px / 弹窗 8px）
- [ ] 阴影是否使用规范层级，有无过重阴影

**E. 组件**
- [ ] 按钮：类型使用是否恰当、一行主按钮是否 ≤3 个、加载态是否禁用点击
- [ ] 表格：行高 ≥40px、表头是否灰底、数字右对齐、长文本是否省略号 + tooltip、操作列间距
- [ ] 表单：Label 是否对齐统一、必填是否红 `*`、错误提示是否具体
- [ ] 弹窗：宽度是否匹配内容、遮罩与圆角是否正确、按钮是否右对齐

**F. 状态完整性**（最容易被漏掉的一项）
- [ ] 空数据态、加载中态、加载失败态
- [ ] 无权限 / 禁用态
- [ ] 超长内容、极端数据的处理
- [ ] 表单校验与错误定位

**G. 交互与可访问性**
- [ ] 所有可点击元素有 hover 与 focus 态
- [ ] 键盘可聚焦，有可见焦点环
- [ ] 危险操作有二次确认
- [ ] 图片有 alt、图标按钮有无障碍标签
- [ ] 文案：按钮用动词开头、错误信息说清"怎么改"、空态给出下一步动作

**H. 一致性**
- [ ] 同类型元素跨页面是否一致
- [ ] 同类操作的位置是否固定（如主操作统一在右上）
- [ ] 日期 / 金额 / 单位格式是否统一

### 第 3 步：输出问题清单

按严重级别分组，每条包含：**位置 → 问题 → 规范依据 → 修复建议**。

| 级别 | 含义 | 示例 |
|------|------|------|
| 🔴 严重 | 违反硬性规范 / 影响可用性 | 表格行高 32px、主色用错、无空态 |
| 🟡 中等 | 不一致 / 细节粗糙 | 间距非 4 倍数、数字未右对齐 |
| 🔵 建议 | 可优化项 | 图标与文字间距可收紧至 4px |

### 第 4 步：给出结论

- 汇总问题数量与分布
- 明确指出"必须改 / 建议改"
- 给出可执行的下一步（哪几处先改）

## 输出示例

> **走查对象**：`src/views/user/UserList.vue`
> **结论**：3 项严重、2 项中等、1 项建议。
>
> | 级别 | 位置 | 问题 | 规范依据 | 修复建议 |
> |------|------|------|----------|----------|
> | 🔴 | 表格行 | 行高 36px | 行高 ≥40px | 改为 48px（紧凑 40px） |
> | 🔴 | 空数据 | 未实现空态 | 空态为必备状态 | 增加占位插图 + "暂无数据" + 新建按钮 |
> | 🟡 | 卡片 | padding 20px | 卡片内边距 24px | 统一为 24px |
> | 🔵 | 工具按钮 | 图标与文字间距 8px | 建议 4px | 收紧至 4px |

## 注意

- 只报告**有规范依据**的问题，不做主观审美评判
- 区分"违反规范"与"规范未覆盖"，后者单独列为建议
- 每条问题都要可定位、可修复，避免"整体感觉不够精致"这类无效反馈
